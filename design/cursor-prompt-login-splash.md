# برومبت Cursor — تركيب شاشتي الدخول والافتتاحية في LiftCore

معايا ملفين HTML جاهزين بتصميم وحركة نهائية: شاشة دخول وشاشة ترحيب (افتتاحية).
ارفعهم في مجلد المشروع جنب الملفات اللي بتسلّمها لـ Cursor، وبعدين الصق البرومبت اللي تحت الخط.

**أسماء الملفين:**
- `liftcore-login-premium.html`
- `liftcore-splash-premium.html`

---

عندي مشروع Flask + SQLite + Jinja2 اسمه LiftCore. فيه `app.py` و `templates/base.html` وصفحات موجودة وصفحة داش بورد. ومعايا ملفين HTML جاهزين بتصميم وحركة نهائية لا أريد تغييرهما إطلاقاً.

## القاعدة الأهم (التزم بها حرفياً)

**لا تغيّر أي شيء في تصميم أو حركة الملفين.** ممنوع تعديل أي CSS، أي keyframes، أي قيمة وقت (animation-delay / duration)، أي لون، أي خط، أو أي كود JavaScript خاص بالحركة. مهمتك **التركيب والربط فقط**، مع إبقاء السلوك البصري مطابقاً 100% لما في الملفين. لو احتجت تضيف كوداً (مثل ربط نموذج الدخول بالسيرفر)، أضفه **بدون حذف أو تعديل** السطور الموجودة، وفي المكان المعلَّم بالتعليقات داخل الملفين.

افحص الملفين أولاً وافحص `app.py` و `base.html` وصفحة الدخول الحالية (إن وُجدت) قبل أي خطوة.

## 1) تحويل الملفين إلى قوالب Flask

- انسخ `liftcore-login-premium.html` إلى `templates/login.html` كما هو حرفياً.
- انسخ `liftcore-splash-premium.html` إلى `templates/welcome.html` كما هو حرفياً.
- **هذان القالبان مستقلان — لا تجعلهما يرثان `base.html`** (لا `{% extends %}`)، لأنهما شاشتان كاملتان بخلفية خاصة وبدون سايدبار. اتركهما صفحتين قائمتين بذاتهما.
- خطوط Google Fonts (Tajawal + Cormorant Garamond) مُحمّلة عبر `<link>` داخل الملفين — أبقها كما هي.

## 2) الـ Routes في app.py

أضِف/عدّل بحيث يكون التدفق: **دخول → ترحيب → داش بورد**.

```
GET  /login        → يعرض login.html (لو المستخدم مسجّل دخول بالفعل، حوّله مباشرة إلى /dashboard)
POST /login        → تحقّق من اسم المستخدم وكلمة المرور مقابل جدول المستخدمين الموجود
                       - نجاح: أنشئ الجلسة ثم redirect إلى /welcome
                       - فشل: أعد عرض login.html مع رسالة خطأ (انظر الجزء 4)
GET  /welcome      → يعرض welcome.html (محميّة: تتطلب تسجيل دخول)
GET  /dashboard    → صفحة الداش بورد الحالية (محميّة)
GET  /logout       → أنهِ الجلسة و redirect إلى /login
```

استخدم نفس آلية المصادقة/الجلسة الموجودة في المشروع (نفس جدول المستخدمين ونفس طريقة تشفير كلمة المرور). لا تنشئ نظام مستخدمين جديداً إذا كان موجوداً — اربط بالموجود. لو لم يوجد، استخدم `session` من Flask وجدول users بسيط مع `werkzeug.security` (check_password_hash).

احمِ `/welcome` و `/dashboard` بديكوريتر تسجيل دخول (إن لم يوجد، أنشئ `@login_required` بسيطاً يفحص `session` ويحوّل إلى `/login`).

## 3) ربط نموذج الدخول (login.html) بالسيرفر — بأقل تدخل

داخل `login.html` يوجد `<form id="loginForm">` فيه حقلان `id="user"` و `id="pass"`، وزر `id="loginBtn"`، وفي آخر السكريبت تعليق يشير لمكان الربط بـ Flask.

اربطه بطريقة تُبقي حركة زر التحميل (spinner) كما هي. الطريقة المفضّلة **بدون تغيير شكل الصفحة**:
- لفّ الحقول بإضافة `name="username"` و `name="password"` على الـ `<input>` (إضافة attribute فقط، لا تغيّر غير ذلك).
- اجعل الـ form يرسل POST إلى `/login`. أبسط حل: أضِف `action="/login" method="POST"` على وسم `<form>` الموجود، وأبقِ معالج الـ JavaScript الحالي يعرض الـ spinner ثم يترك الإرسال الطبيعي يحدث (عدّل `e.preventDefault()` بحيث يُظهر الـ spinner ثم `form.submit()` فعلياً، بدل التايمر التجريبي). هذا التغيير الوحيد المسموح في JS وهو ضروري للربط — ولا يمس الحركة.

> ملاحظة: المشروع RTL ويستخدم سياق LTR على اسم LiftCore عمداً (`direction:ltr` على `.wordmark`) لمنع انعكاس الحروف. **لا تلمس هذا الإعداد** — هو ما يجعل الاسم يُقرأ LiftCore بشكل صحيح.

## 4) رسالة خطأ الدخول (بنفس الستايل، دون كسر التصميم)

عند فشل الدخول، مرّر متغيّر `error` للقالب واعرضه برسالة صغيرة فوق الزر أو تحت العنوان. **نسّقها بنفس لغة التصميم** (لون تحذيري خافت يتناغم مع الثيم الذهبي/الأسود، خط Tajawal، حجم صغير) — لا تستخدم تنبيه bootstrap أو ستايل غريب عن الصفحة. مثال للإدراج داخل `login.html` فقط عند وجود خطأ:

```jinja
{% if error %}<div style="color:#e0794a;font-size:12.5px;text-align:center;margin-bottom:14px;letter-spacing:.02em">{{ error }}</div>{% endif %}
```

ضعه داخل `.card` قبل الـ `<form>`.

## 5) اسم المستخدم في شاشة الترحيب (welcome.html)

داخل `welcome.html` يوجد `<span ... id="userName">مهندس محمد</span>` وتعليق يشير إلى أن الاسم يأتي من جلسة Flask.

- استبدل النص الثابت بقيمة من الجلسة: `id="userName">{{ current_user_name }}` (مرّر `current_user_name` من الـ route من اسم المستخدم الحالي). أبقِ الـ `<span>` والكلاسات كما هي — استبدل النص الداخلي فقط.

## 6) الانتقال التلقائي من الترحيب إلى الداش بورد

داخل `welcome.html` يوجد في آخر السكريبت `setTimeout` فيه تعليق `/* window.location.href = '/dashboard'; */` يُنفّذ بعد انتهاء الحركة (حوالي 5 ثوانٍ + تلاشي 0.7 ثانية).

- فعّل هذا السطر **كما هو** ليحوّل إلى `/dashboard`. لا تغيّر مدة الـ `setTimeout` ولا حركة التلاشي — هي مضبوطة لتنتهي بعد اكتمال ظهور الاسم والترحيب.
- (اختياري مستحسن) لتجنّب ظهور الترحيب في كل تنقّل: اجعل `/welcome` يعرض نفسه مرة واحدة بعد الدخول فقط — مثلاً ضع علامة في الجلسة `session['just_logged_in']=True` عند نجاح POST /login، و`/welcome` يتحقق منها ثم يمسحها؛ لو دخل أحد على `/welcome` مباشرة بدونها، حوّله إلى `/dashboard`. لا تغيّر القالب لذلك — المنطق في الـ route فقط.

## 7) ما يجب ألا تفعله (تأكيد)

- لا تضف Tailwind ولا Bootstrap ولا أي مكتبة CSS لهذين القالبين.
- لا توحّد ألوانهما مع base.html ولا تنقل ستايلهما لملف خارجي — اتركه inline داخل كل قالب كما سُلّم.
- لا تعِد ترتيب عناصر HTML ولا تعِد تسمية الكلاسات.
- لا تغيّر روابط الخطوط ولا أسماء عائلات الخطوط.

## 8) بعد الانتهاء

اكتب لي ملخصاً:
- الملفات التي أُضيفت/عُدّلت بالضبط (ويُفضّل أن تكون: `templates/login.html`, `templates/welcome.html`, وتعديلات محصورة في `app.py`).
- أوامر التشغيل للتجربة.
- وأكّد صراحةً أنك لم تعدّل أي CSS أو keyframes أو JavaScript خاص بالحركة في الملفين.

ابدأ بفحص الملفين و app.py، ثم نفّذ الخطوات بالترتيب.

## للتجربة بعد التنفيذ
شغّل المشروع وافتح `/login` — لازم تشوف نفس الحركة بالظبط (خط الضوء الصاعد + تجمّع اسم LiftCore + خط الإدخال الذهبي عند الكتابة). سجّل دخول صحيح → لازم تروح لشاشة الترحيب بنفس حركتها → بعد ~5 ثوانٍ تنتقل تلقائياً للداش بورد. جرّب دخول خاطئ → لازم تشوف رسالة الخطأ بنفس ستايل الصفحة من غير ما يتكسر التصميم.

## نصيحة تنفيذ
نفّذ على مرحلتين في Cursor: (1) نسخ القالبين + الـ routes + الحماية وجرّب الدخول، (2) ربط الفورم + رسالة الخطأ + اسم المستخدم + الانتقال التلقائي. اعمل commit بعد كل مرحلة.
