# LiftCore — استراتيجية i18n (J1–J3 + G2)

**آخر تحديث:** يوليو 2026

## الوضع الحالي

| الطبقة | الآلية | الحالة |
|--------|--------|--------|
| واجهة المكتب | `liftcore-i18n.js` + `liftcore-translations.js` | ✅ عربي افتراضي + EN عند التبديل |
| طباعة PO | قوالب ثنائية (`print` / `print-en`) | ✅ |
| رسائل API | `liftcore_api_i18n.py` | ✅ `message` + `message_ar` + `message_en` |
| محتوى ديناميكي (أسماء عملاء، ملاحظات) | بدون ترجمة تلقائية | قرار أدناه |

## J1 — مراجعة EN

- الملف المرجعي: `static/liftcore-translations.js`
- الاختبار: `tests/test_i18n_translations.py` — يتحقق أن كل مفتاح عربي له ترجمة EN غير فارغة
- عند إضافة نص عربي جديد في القوالب أو JS: أضف السطر في ملف الترجمة

## J2 — API ثنائي اللغة

استخدم في routes جديدة:

```python
from liftcore_api_i18n import api_json_error, api_error_payload

return api_json_error('not_found', 404)
```

اللغة تُحدَّد من `session['lang']` أو رأس `X-LC-Lang: en`.

## J3 — المحتوى الديناميكي

**القرار للتسويق (P2):** لا نترجم أسماء العملاء/العناوين/الملاحظات الحرة تلقائياً.

| الخيار | قرار |
|--------|------|
| حقول `name_en` / `address_en` في النماذج | يُشجَّع يدوياً عند الحاجة |
| `/api/translate` (G2) | **مؤجّل P3** — تكلفة API + دقة قانونية/مالية |
| ZATCA / فواتير | عربي رسمي؛ EN اختياري في الطباعة حيث وُجد |

## G2 — `/api/translate`

غير مُنفَّذ عمداً. إعادة التقييم عند:

- طلب عملاء متعددين لمحتوى ديناميكي EN
- أو دمج مزوّد ترجمة معتمد في العقد
